# TripMind 启动与交付

更新：2026-10-21。当前交付目标是本地 MSc 项目演示，不是公开生产服务。

## 本机演示

双击项目根目录的 **Start-TripMind.command**，或在项目根目录运行：

```sh
.venv/bin/python scripts/start.py --preview
```

打开 http://127.0.0.1:5173 。终端保持打开；按 Ctrl+C 同时停止前后端。端口被占用时脚本会报错，不会杀死已有服务。开发模式去掉 `--preview`；改过前端源码后，演示模式需要先在 frontend 运行 `npm run build`。

本机密钥已经配置，不需要重新提供。改动 backend/.env 后重启服务。健康检查 `/api/health` 只确认服务和配置模式，不代表 Qwen 余额或连通性。

## 新电脑安装

需要 Python 3.10+、Node.js（满足 Vite 的 Node 20.19+ 或 22.12+ 版本要求）、npm 和网络。本轮验证环境为 macOS / Python 3.14.7 / Node 26.12.0；其他系统尚未实际验证。脚本针对 macOS/Linux。

1. 解压源代码到可写目录，终端进入该目录。
2. 运行 `bash scripts/setup.sh`：建立虚拟环境、安装锁定依赖、构建并运行测试。已存在的 .env 不会被覆盖。
3. 在本地编辑 backend/.env，填写百炼 DASHSCOPE_API_KEY，确认模型和 endpoint 同一地域；不要把密钥放到前端。
4. 运行上方启动命令，打开固定地址。

无密钥演示：`.venv/bin/python scripts/start.py --preview --sample`。样例只支持 London、连续两天、1–4 人；不会调用 Qwen。天气仍按 WEATHER_ENABLED 配置；完全离线时会降级。

## 使用范围与验收

Qwen：17 个英国城市、1–14 天（包含首尾）、1–50 人、GBP 整团预算。活动明细为每人费用，分类为整团费用。跨城市到达交通不含在预算中。天气超出预报窗口或请求失败时明确显示不可用，仍允许生成。

超过三天的行程先由 Qwen 生成全局景点分配表（每天两个主要地点），校验名称唯一后，再以最多三天一段、最多三段并行的方式补充时间、餐次、费用与天气说明。各段必须覆盖当天分配的地点；模型额外增加的独立活动会被剔除，保留原路线的交通估计并重新检查时间间隔，原分类费用保留为保守估算且明确提示。不能安全拆分的组合活动或缺失的主要景点仍触发修正。14 天正常六次模型调用（一次分配 + 五段详情），每次最多一次输出修正，上限十二次。网络单次超时不超过 120 秒，整体使用约 420 秒时间预算、浏览器 450 秒；配额、网络或输出重试仍可能导致失败。校验仍发现重复时返回明确失败，不把已知重复方案当成功结果。名称检查含部分常见别名，不能替代地理实体核验。费用超预算会明确显示，不保证优化到预算内。

检查：生成 → 检查天数和金额 → Save Trip → 刷新 → My Trips → View Plan。保存仅在当前浏览器 localStorage，清除浏览器数据会丢失；localhost 和 127.0.0.1 是不同存储来源，统一使用上述地址。

## 可交付内容

`dist/TripMind-source.zip`：可重建的前后端源代码、依赖锁、测试、启动脚本、说明文档。重新打包：`python3 scripts/package_delivery.py`。不含密钥、虚拟环境、node_modules、个人浏览器存档、原始模型记录；接收方自行安装依赖并配置密钥。这是源代码包，不是无需安装的桌面应用。

最终固定案例验收见 [Acceptance-2026-10-22.md](Acceptance-2026-10-22.md)，包含成功率、耗时、问题和复现命令。前期回归说明见 [Testing-2026-10-21.md](Testing-2026-10-21.md)。截图和本地合成测试输入输出在 experiments/hardening-2026-10-21/，不纳入源代码包。

公开上线还需要生产 WSGI 服务、TLS、访问控制、限流与费用保护、部署配置和相应验证；当前启动器只绑定本机。景点真实性、价格、营业时间、路线和天气分类仍需人工核验。
